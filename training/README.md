# QLoRA Fine-tuning — HospitalRAG

Fine-tune a local LLM on Houston Memorial Hospital synthetic KB data using QLoRA (Quantised Low-Rank Adaptation).

## Directory Structure

```
training/
  prepare_dataset.py   — Generate instruction pairs from KB JSON
  train_qlora.py       — QLoRA trainer (configurable, requires --run flag)
  evaluate.py          — Compare base vs fine-tuned model metrics
  export_model.py      — Merge adapter + optional GGUF export
  register_ollama.sh   — Register merged model with Ollama
  requirements.txt     — Python dependencies
  data/
    train.jsonl        — Generated by prepare_dataset.py (90%)
    val.jsonl          — Generated by prepare_dataset.py (10%)
  outputs/
    qlora-adapter/     — Saved LoRA adapter (base model untouched)
    merged/            — Merged HF model (post export_model.py)
    gguf/              — GGUF file (post export_model.py --gguf)
    eval_results.json  — Evaluation metrics
```

## Setup

```bash
cd training

# Create isolated environment
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux/macOS

pip install -r requirements.txt
```

## 1. Prepare Dataset

Reads `../data/*.json` (1,200 synthetic records) and generates Alpaca-format JSONL:

```bash
python prepare_dataset.py
# Output:
#   data/train.jsonl  (~2,400+ pairs)
#   data/val.jsonl    (~270+ pairs)
```

Options:
```
--data-dir   ../data       Path to KB JSON files
--output-dir data          Output directory
--seed       42            Random seed (deterministic)
--train-split 0.9         Train fraction
```

## 2. Dry Run (Validate Config)

Always validate before training:

```bash
python train_qlora.py \
  --model microsoft/phi-3-mini-4k-instruct \
  --dry-run
```

## 3. Train

```bash
python train_qlora.py \
  --model microsoft/phi-3-mini-4k-instruct \
  --train-file data/train.jsonl \
  --val-file   data/val.jsonl \
  --output-dir outputs/qlora-adapter \
  --lora-r 16 --lora-alpha 32 --lora-dropout 0.1 \
  --epochs 3 --batch-size 4 --grad-accum 4 \
  --lr 2e-4 --max-seq-len 512 \
  --logging-steps 10 \
  --run
```

> **Note**: The `--run` flag is required as a safety gate. The base model is **never modified**. Only the LoRA adapter is saved.

Alternative base models:
- `microsoft/phi-3-mini-4k-instruct` — 3.8B params, 16 GB VRAM
- `meta-llama/Llama-3.2-3B`         — 3B params, 16 GB VRAM (requires HuggingFace access)
- `mistralai/Mistral-7B-Instruct-v0.3` — 7B params, 24 GB VRAM

## 4. Evaluate

```bash
# Offline (on pre-saved predictions):
python evaluate.py --mode offline \
  --predictions outputs/predictions.jsonl \
  --test-file   data/val.jsonl

# Compare base vs fine-tuned (requires GPU):
python evaluate.py --mode compare \
  --base-model microsoft/phi-3-mini-4k-instruct \
  --adapter-dir outputs/qlora-adapter \
  --test-file   data/val.jsonl \
  --n-samples   50
```

Metrics reported:
| Metric | Description | Target |
|---|---|---|
| Template completeness | Fraction of required SOAP/domain fields present | > 0.90 |
| Field accuracy | Token overlap with ground truth | > 0.70 |
| Hallucination rate | Tokens absent from context (proxy) | < 0.20 |

## 5. Export to GGUF

```bash
# Merge adapter into base model
python export_model.py \
  --base-model microsoft/phi-3-mini-4k-instruct \
  --adapter-dir outputs/qlora-adapter \
  --output-dir  outputs/merged

# With GGUF conversion (requires llama.cpp in PATH)
python export_model.py --gguf --gguf-quantize q4_k_m
```

## 6. Register with Ollama

```bash
bash register_ollama.sh
```

Then update `backend/.env`:
```
OLLAMA_MODEL=hospitalrag-v1
```

No backend code changes needed — `OllamaClient` reads `OLLAMA_MODEL` from env.

## Hardware Requirements

| Component | Minimum | Recommended |
|---|---|---|
| GPU VRAM | 16 GB (phi-3-mini) | 24 GB (Llama-3.2-3B or 7B models) |
| RAM | 32 GB | 64 GB |
| Storage | 30 GB free | 60 GB free |
| CUDA | 11.8+ | 12.1+ |

> CPU-only training is possible but extremely slow (days instead of hours). Not recommended for production.

## Resume Training

```bash
python train_qlora.py \
  --model microsoft/phi-3-mini-4k-instruct \
  --resume-from outputs/qlora-adapter/checkpoint-100 \
  --run
```

## PII Note

All dataset records use SHA-256 masked IDs (`PAT-`, `MED-`, `INS-`, `INV-`). **No real patient data is present.** Masked IDs must appear unchanged in SOAP `Sources` fields — never decoded.
