# MediNexa Hospital RAG Assistant

MediNexa is an internal hospital knowledge assistant. It retrieves relevant patient, medicine, instrument, and inventory records from the existing knowledge base, then uses Groq to produce a source-grounded, structured answer.

## Local setup

Install the backend and frontend dependencies:

```bash
cd backend
npm install

cd ../frontend
npm install
```

Create `backend/.env` from `backend/.env.example` and set the server-side configuration:

```dotenv
PORT=5000
DATABASE_URL=postgresql://postgres:password@localhost:5432/hospital_rag
GROQ_API_KEY=your_groq_key_here
GROQ_MODEL=llama-3.1-8b-instant
KB_DATA_DIR=../data
```

`GROQ_API_KEY` is read only by the Express backend. Do not put it in `frontend/.env` or use a `VITE_`-prefixed variable.

Start the services:

```bash
cd backend
npm start

cd ../frontend
npm run dev
```

The backend runs on `http://localhost:5000`; the frontend defaults to that URL through `VITE_API_URL`.

## RAG flow

```
React chat UI → Express API → PostgreSQL-backed chat persistence + retrieval
             → retrieved context + existing prompts → Groq (llama-3.1-8b-instant)
             → existing validation/formatting → chat response
```

If Groq is unavailable, MediNexa preserves its retrieval-only fallback response. The existing response formats, retrieved source IDs, prompts, and UI behaviour remain the same.

## Configuration

| Variable | Purpose | Default |
| --- | --- | --- |
| `GROQ_API_KEY` | Backend-only Groq API key | required |
| `GROQ_MODEL` | Groq generation model | `llama-3.1-8b-instant` |
| `DATABASE_URL` | PostgreSQL connection string | local PostgreSQL URL |
| `PORT` | Express server port | `5000` |
| `KB_DATA_DIR` | Knowledge-base data directory | `../data` |

## Verification

Run the local test suites from the repository root:

```bash
node --test tests/test_retrieval.js tests/test_chat.js tests/test_account6.js
```

With PostgreSQL and `GROQ_API_KEY` configured, create a chat in the UI and submit a knowledge-base query. The response includes retrieved source IDs and is generated by Groq on the backend.
